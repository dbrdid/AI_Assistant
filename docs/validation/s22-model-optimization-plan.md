# S22 모델 경량화·보정 계획

상태: 계획 확정, 실행 전. 목표는 `s22-performance-goal.md`의 합격 기준이다. 기법을 많이 적용하는 것이 아니라, 기준을 통과하는 가장 단순한 조합을 채택한다.

## 현재 제약

- 학습 PC: RTX 3060 Laptop 6GB, RAM 15.7GB, 디스크 여유 34.3GB.
- 설치된 학습 도구: 없음(torch, transformers, peft, llama.cpp 양자화 도구 미설치).
- 보유 가중치: Q4_K_M, Q5_K_M GGUF만 있다. GGUF만으로는 재학습이나 재양자화를 할 수 없다.
- 모델 라이선스: Apache-2.0.
- 런타임 제약: 결과물은 `llama.rn`에서 로드되는 GGUF여야 한다.

## 단계

### A. 코드 기반 경량화 (다운로드 없음, 지금 진행)

1. 명확한 앱 명령은 규칙 기반 라우터로 처리해 모델 호출을 생략한다.
2. `llama.rn`이 지원하면 앱 명령에 JSON 스키마 또는 문법 제약을 적용한다.
3. 작업별 입력·출력 상한을 둔다. 긴 문서는 관련 블록만 전달한다.
4. 메모리·발열 상태에 따라 긴 요약 같은 무거운 기능을 제한하고 이유를 안내한다.
5. 신뢰도 보정: 근거 부족, 검증 실패, 모호한 대상은 실행하지 않고 되묻는다. 임계값은 보정 전용 합성셋으로 정한다.

### B. 재양자화 비교 (다운로드 승인 후)

Q4_K_M(2.81GiB)과 IQ4_XS(2.49GiB), Q3_K_M(2.40GiB)을 같은 조건으로 비교한다. 품질 저하 없이 메모리와 속도가 개선될 때만 교체한다.

### C. QLoRA 파인튜닝 (다운로드 승인 후, A·B로 부족할 때)

앱 명령 JSON, 날짜·숫자 보존, 근거 부족 시 거절을 합성 데이터로 학습한다. 6GB VRAM 한계에 맞춰 4비트 로드와 작은 배치를 쓰고, 병합 후 GGUF로 변환한다.

### D. 지식 증류 (C로 부족할 때)

Q4 또는 BF16을 교사로 삼아 의도 분류·슬롯 추출용 소형 모델을 먼저 만든다. 전체 대화 모델의 교체는 소형 모델이 기준을 넘고 품질 기준도 지킬 때만 검토한다.

### E. 가지치기·구조 탐색 (최후 수단)

가중치를 0으로 만드는 희소화는 GGUF 크기와 추론 시간을 줄이지 못하므로 제외한다. 레이어·헤드를 실제로 제거하는 구조 변경만 검토하며, `llama.rn` 로드와 한국어 품질을 먼저 소규모로 검증한다.

## 데이터와 평가 규칙

- 데이터를 학습, 보정, 개발, 최종 평가로 분리하고 해시를 기록한다.
- 독립 300문항은 학습, 임계값 조정, 프롬프트 조정, 후보 선택에 쓰지 않는다. 최종 후보 1개와 기준 Q4 평가에만 쓴다.
- 합성 데이터만 사용한다. 실제 사용자 문서는 사용하지 않는다.
- 모델이나 출력 설정이 바뀌면 이전 300문항 점수를 최종 결과로 쓰지 않는다.

## 채택 기준

- 필수 품질 기준을 유지하면서 메모리, 첫 토큰, 지속 속도 중 하나 이상이 측정으로 개선되어야 한다.
- 입력 검증, 승인 절차, 저장 후 검증을 약화시키지 않는다.
- 후보는 기존 Q4로 되돌릴 수 있어야 한다.
- 실기기 성능 판정은 S22 측정 후에만 PASS로 기록한다.
