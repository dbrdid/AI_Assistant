# Galaxy S22 쾌적 동작 목표

상태: 목표 확정, 실기기 측정 전. 아래 수치는 합격 기준이며 측정값이 아니다. 모든 항목의 현재 결과는 `NOT_RUN`이다.

## 기준 기기와 현재 설정

- 기준 기기: Galaxy S22 8GB. 측정 시 SoC, One UI, 빌드 번호, 배터리 상태, 실내 온도를 기록한다.
- 기본 모델: Q4_K_M(3.01GB). 현재 정책상 Q5_K_M은 총 RAM 11GB 이상에서만 로드되므로 S22 8GB에서는 쓰지 않는다.
- 현재 추론 설정: Android CPU(`n_gpu_layers: 0`), `n_ctx: 4096`, `n_batch: 128`, `n_ubatch: 64`, `n_predict: 512`, mmap 사용.
- 현재 로드 조건: 사용 가능 메모리 3.01GB + 700MiB 이상. mmap 모델에도 전체 크기를 요구하므로, S22에서 로컬 AI가 자주 거부될 위험이 있다.

## 합격 기준

빌드는 release, 기기는 비행기 모드, 충전 해제, 배터리 50% 이상, 합성 데이터 사용을 기본으로 한다. 지연 시간은 항목별 30회 이상의 P95다.

| 영역 | 지표 | 합격 기준 |
|---|---|---|
| 앱 기본 | 콜드 스타트 후 조작 가능 | 2.5초 이하 |
| 앱 기본 | 문서 열기(블록 500개) | 500ms 이하 |
| 앱 기본 | 블록 입력·이동 반응 | 100ms 이하 |
| 화면 | 추론 중 스크롤·입력 | 느린 프레임 5% 이하, 700ms 이상 멈춘 프레임 0, ANR 0 |
| 모델 | 첫 로드 / 재로드 | 20초 이하 / 8초 이하 |
| AI 응답 | 짧은 앱 명령의 첫 토큰 | 4초 이하 |
| AI 응답 | 512토큰 입력의 첫 토큰 | 8초 이하 |
| AI 응답 | 블록 명령 요청부터 승인 카드까지 | 10초 이하 |
| AI 응답 | 15분 지속 생성 | 평균 10 tok/s 이상, 마지막 5분이 처음 5분의 70% 이상 |
| 제어 | 취소 후 생성 중단 | 500ms 이하 |
| 메모리 | 로드·생성·해제 30회 반복 | OOM·앱 강제 종료 0, 해제 후 기준선 대비 +200MB 이하 |
| 메모리 | 일반 앱 동시 사용 | 다른 앱 3개를 띄운 상태에서도 로드 성공 또는 명확한 안내, 문서 데이터 손실 0 |
| 발열·전력 | 15분 지속 생성 | `THERMAL_STATUS_SEVERE` 미만, 배터리 온도 43°C 이하, 배터리 소모 5% 이하 |
| 오프라인 | 비행기 모드 전체 흐름 | 추론, 승인, 저장, 재시작 후 보존 성공 |
| 품질 | S22 설정의 Q4 독립 300문항 | JSON 99% 이상, 블록 명령에서 주변 블록 변경 0 |

## 개선 순서

1. 측정 도구를 먼저 만든다. 개발 빌드에서만 켜지며 위 지표를 JSON으로 저장한다.
2. 로드 조건을 mmap 동작에 맞게 재검토한다. 실패해도 앱과 문서 기능은 계속 동작해야 한다.
3. 작업별 출력 상한을 둔다. 앱 명령은 필요한 JSON 길이에 맞추고 긴 요약만 큰 상한을 쓴다.
4. 고정 시스템 프롬프트의 재평가를 줄일 수 있는지 확인한다.
5. 실기기에서 `n_threads`, `n_ctx`, `n_batch`, `n_ubatch`를 한 번에 하나씩 비교한다. 측정 없이 값을 바꾸지 않는다.
6. 기준 미달이면 GPU 가속이나 더 작은 모델을 후보로 올린다. 새 모델이나 의존성은 사용자 승인 후에만 추가한다.

## 판정 규칙

- 실기기에서 측정한 항목만 PASS로 기록한다. PC, 에뮬레이터, 번들 성공은 S22 통과 근거가 아니다.
- 속도를 위해 입력 검증, 승인 절차, 저장 후 검증을 줄이지 않는다.
- S22 설정이 모델 출력에 영향을 주면 300문항 평가는 그 설정을 고정한 뒤 실행한다.
