# Stella AI 게이트웨이

AI 작업 공간은 같은 모드의 요청에 공통 앱 지침을 적용한다. AI가 제안한 앱 명령은 사용자가 변경 내용을 검토하고 승인한 뒤 앱이 실행한다.

## 연결 설정

**AI 작업 공간 → AI 연결**에서 제공자를 고른다.

| 연결 | 설정 방법 |
| --- | --- |
| 이 기기 | 기본 모델은 Gemma 4 E2B다. 처음에는 **Gemma 4 E2B 다운로드**를 누르고, 설치된 모델은 **기기 모델**에서 선택한다. |
| 내 서버의 로컬 LLM | 기기에서 접근할 수 있는 서버 주소를 입력한다. OpenAI 호환 주소는 `/v1`까지 입력해도 된다. 인증이 필요하면 서버 키를 입력한 뒤 **서버에서 불러오기**로 모델을 선택한다. |
| Stella 클라우드 AI | Stella 계정으로 로그인하고 AI 설정에서 외부 전송을 허용한다. 앱은 Supabase의 `/command`로 요청하며 계정의 `query_plan` 이용 한도를 함께 쓴다. |
| 내 OpenAI 계정 | 사용할 모델 이름과 본인 OpenAI API 키를 입력하고 **이번 실행에만 키 사용**을 누른다. |
| 내 Anthropic 계정 | 사용할 모델 이름과 본인 Anthropic API 키를 입력하고 **이번 실행에만 키 사용**을 누른다. |

ChatGPT·Claude 구독 로그인으로는 Stella의 API 호출을 인증할 수 없다. 개인 계정 연결에는 해당 제공자의 API 키가 필요하다. 앱은 입력한 키를 실행 중 메모리에만 보관하며, 재시작하면 다시 입력해야 한다.

기본 기기 모델 파일은 `ggml-org/gemma-4-E2B-it-GGUF`의 Q4_0이며 2,841,481,184바이트, Apache-2.0이다. 다운로드 리비전은 고정되어 있고 파일을 SHA-256으로 검사한다. 로드에 필요한 가용 메모리 1.5 GiB는 S22 실측 전 임시값이다. 개인 서버에 연결할 때 Android는 평문 통신 설정에 따라 HTTP를 차단할 수 있고, 웹에서는 서버가 앱 출처에 대해 CORS를 허용해야 할 수 있다.

## 요청에서 저장까지

1. 앱이 먼저 규칙으로 요청을 해석한다. 명령이 정해지면 AI 호출을 건너뛰고 **앱 작업 검토**로 진행한다.
2. AI 해석이 필요하면 게이트웨이가 앱 지침과 사용자 요청으로 프롬프트를 구성하고 선택한 제공자에서 텍스트 응답을 받는다.
3. 대화 모드에서는 응답 중 `앱 작업:`으로 시작하는 첫 줄만 명령 후보로 읽는다. 표시가 없으면 일반 답변으로 보여 준다. 전용 **앱 작업 해석** 모드에서는 기존 명령 형식의 첫 줄을 읽고, `지원불가`이면 되묻는다.
4. 사용자가 **앱 작업 검토**에서 대상과 변경 내용을 확인하고 승인하면 앱이 권한을 확인해 저장한다. 저장 후에는 작업별 결과를 검증한다. 예를 들어 할 일을 연결하면 저장된 할 일의 프로젝트 ID를 다시 읽어 대상과 대조한다.

## 프로젝트 명령

| 명령 예시 | 승인 결과 |
| --- | --- |
| `프로젝트 만들기: 신제품 출시` | ‘진행 전’ 상태로 생성하고 상세 화면을 연다. “신제품 출시라는 프로젝트 만들어줘”도 규칙으로 해석한다. |
| `프로젝트 상태 변경: 신제품 출시 / 진행 중` | 해당 프로젝트의 상태를 바꾼다. 가능한 상태는 진행 전, 진행 중, 완료, 보류다. |
| `할 일 프로젝트 연결: 포스터 제출 / 신제품 출시` | 기존 할 일 ‘포스터 제출’을 프로젝트 ‘신제품 출시’에 연결한다. |
