## 2. 결과·품질·증거를 분리

결과: PASS(해당 범위·기준 전부 충족), FAIL(관찰된 위반), NOT_RUN(선행조건은 있으나 미실행), BLOCKED(선행조건 부재), N/A(범위 제외 승인과 사유 있음). FAIL은 심층 시험을 했다는 이유로 점수를 얻지 못한다. 부분 시험 PASS는 별도 하위 실행에만 기재하며 상위 수용 시험은 필요한 증거가 없으면 BLOCKED/NOT_RUN으로 남긴다.

증거: L0 제안/보고, L1 소스 검토, L2 합성/모의 구성요소 실행, L3 실제 서버·DB·모델 연결, L4 실제 기기·두 기기·복구, L5 목표 부하·운영 조건. 수준은 품질 점수가 아니며 더 높은 숫자가 모든 낮은 시험을 대신하지도 않는다. 작성자 실행과 평가자 독립 재실행을 구분한다.

품질 점수는 각 지표의 사전 승인된 품질 함수와 가중치로만 계산한다. 지표마다 `metric, unit, population, target, scoring_function, weight, min_evidence`를 고정한다. 합격 목표만 정의한 이진 항목은 기준을 충족하는 PASS에만 100, FAIL에 0을 주며 증거가 없으면 unknown이다. 연속 점수는 사전 승인한 함수가 없으면 이진으로만 판정한다. evidence 점수는 별도로 필요 수준 충족 여부/측정 범위를 보고하며 합산하지 않는다. unknown을 0점이나 제외 항목으로 바꿔 총점을 부풀리지 않는다. 필수 항목 unknown 또는 Gate 미통과가 하나라도 있으면 총합 합격/출시 판정은 불가하다. v1의 0~4 증거 등급 기반 가중 총점과 80점 합격 규칙은 폐기한다. 현재 품질 총점은 **미산정**이다.

## 4. 목표 설정 순서와 사전 안전 기준

순서: (A) 시험 환경·pilot 데이터 고정 → (B) baseline 측정 → (C) 담당자가 품질/지연/비용/부하 목표 승인 → (D) 목표·평가 지침·모델·프롬프트·최종 holdout 해시 동결 → (E) 독립 최종 평가. 최종 결과를 본 뒤 기준을 낮추면 해당 실행을 무효 처리하고 새 평가 세트로 재시험한다. pilot은 최종 점수에 섞지 않는다.

baseline 전에 정하는 안전 조건: 금지 전송·허용 밖 provider 전환·계정 혼입·권한 없는 쓰기·원본/첨부 유실·승인 없는 AI 저장·확인된 중대 사실 오류는 **관찰 0건**이어야 한다. 확인된 1건이면 해당 Gate FAIL이다. 0건이 모집단 오류율 0임을 뜻하지 않는다. 중대 사실 오류는 사람/날짜/금액/해야 할 행동을 바꾸거나 근거 없는 내용을 확정해 사용자 행동에 영향을 주는 오류로 규정하며 pilot에서 판정 예시를 합의한다.

| 지표군 | baseline | 승인 목표 | 승인자·일시·동결 ID | 현재 상태 |
|---|---|---|---|---|
| 안전 불변식 | 불필요 | 위 관찰 0건 조건 | 계획 기준, 출시 책임자 재확인 필요 | 실행 증거 미완성 |

| p50/p95 지연·timeout·메모리 | 미측정 | 미승인 | 미지정 | 최종 평가 BLOCKED |
| 성공 작업당 총비용·동시 부하·복구 시간 | 미측정 | 미승인 | 미지정 | 최종 평가 BLOCKED |
| provider/리전/보관/로그 TTL·동의 문구 | 검토 전 | 미승인 | 개인정보 책임자/전문 검토 필요 | 외부 배포 BLOCKED |

## 5. 표본과 평가자

100개는 초기 pilot 규모일 뿐 오류 부재의 입증 표본이 아니다. 독립 동일 분포 Bernoulli 시행에서 0/n 실패의 단측 95% 정확 상한은 `1 - 0.05^(1/n)`이다. 0/100은 약 2.95%, 0/299는 약 1%, 0/2995는 약 0.1%이다. 원하는 상한 u에는 `ceil(log(0.05)/log(1-u))` 표본이 필요하다. 문서 여러 chunk·같은 원본 재질문은 독립 표본으로 부풀리지 않는다. 실제 표본의 의존/군집과 선택 편향을 보고하고 이 공식의 가정을 충족하지 못하면 상한을 제품 전체 보장으로 해석하지 않는다. 실패가 있으면 0건 공식을 쓰지 말고 적절한 이항 신뢰구간을 계산한다. [NIST 이항 비율 구간](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

두 평가자가 모델/경로를 모르는 상태에서 독립 판정한다. 합의 전 원자료, 단순 일치율, 명목 분류 Cohen's kappa(서열 평가면 사전 정의한 가중 kappa), 혼동표와 범주 분포를 저장한다. 기대 일치율 1이면 kappa는 N/A로 보고한다. 불일치는 제3 평가자가 근거 문장과 지침에 따라 판정하고 기존 두 판단을 지우지 않는다. 평가 지침 수정/평가자 교육은 pilot으로만 수행한다. 일치도 목표도 holdout 전에 승인한다. [일치도와 kappa의 한계](https://pmc.ncbi.nlm.nih.gov/articles/PMC3900052/)

문서 길이·도메인(개인 메모/학업/업무 등)·구어체/오탈자·날짜/금액·표·정보 부재·민감정보·악성 지시·공유 권한·중복 문서별 표본 수와 목표 사용 분포를 manifest에 기록한다. 합성/공개 자료/적법한 동의가 있는 실제 한국어 자료의 비중을 각각 보고한다. 실제 사용자 자료를 자동 수집하지 않는다. 실제 사용 분포를 모르면 외적 타당성은 unknown이며 합성 성적을 시장 성능으로 일반화하지 않는다. 학습/튜닝/pilot/최종 평가를 문서 단위로 분리하고 near-duplicate를 검사한다.

## 6. 전송 시험 V09·V33·V34

독립 기대 정책표를 먼저 작성한다: 사용자 설정 × 문서 제외/삭제 상태 × 계정/공간 × 외부/자체 동의 × 선택 경로. 앱이 반환한 effective policy를 정답으로 쓰지 않는다. V33은 이 표와 실제 설정→기기 차단 분류를 대조한다. V11은 복수 자료의 허용 경로 교집합을 검사한다.

V09/V34는 합성 canary를 본문뿐 아니라 제목·파일명·경로·MIME·문서 속성·계정/공간 메타데이터·예외 메시지·로그·크래시 리포트·분석 이벤트에 서로 다른 표식으로 주입한다. 요약/검색 계획/근거 답변/임베딩/파일 업로드·다운로드/추출·오류·재시도·백그라운드 경로 목록을 작성하고 비활성 경로도 설정·네트워크 증거로 확인한다.

기기→Gateway와 Gateway→provider 두 구간 및 관측/로그 수집 종단의 실제 payload·헤더·쿼리를 격리된 합성 환경에서 캡처한다. 허용 제목까지 포함해 전송 필드 allowlist와 대조한다. 거절 응답 전 금지 표식이 이미 전송되면 FAIL이다. mock 호출 0회는 하위 L2 증거이며 실제 기기 전체 경로 PASS를 대신하지 못한다. 동의 철회 후 후속 hop/재시도, 앱 중단, crash/error, 파일 메타데이터, 다른 계정 캐시를 포함한다. 증거 자체에는 실제 사용자 내용이나 실인증 토큰을 남기지 않는다.

## 8. 비용·성능·판정 기록

작업당 총비용에는 성공/실패/timeout/재시도/fallback의 API 비용, 자체 서버 idle/startup/추론·저장·네트워크·관측 비용을 포함한다. 분모는 승인 품질을 충족한 성공 작업 수이며 0이면 비용 지표를 계산하지 않는다. 사용량/가격을 모르면 unknown으로 두고 0으로 대체하지 않는다. 자체 모델 token count는 API 요금이 아니다. 실제 모델 버전/양자화·입출력 token·동시 요청·cold/warm을 같이 기록한다.

V01~V34의 상위 수용 시험은 현재 배포/기기/모델/목표 등의 선행조건이 없어 BLOCKED이며 원인별 담당을 CSV에 남긴다. 개발 시험 PASS는 아래 실행 문서에만 별도 기록한다. 실패가 확인되면 선행조건 부재에 숨기지 말고 FAIL을 우선 기록하고 원인·재현·수정 commit·재시험을 연결한다. 시험 결과가 생길 때만 상태를 갱신하며 계획서만으로 통과 처리하지 않는다.
