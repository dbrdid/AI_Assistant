# 오늘의 플래너 1.1.0 실기기 감사 (2026-11-24)

대상: S22(SM-S901N, 1080×2340), `com.stella.notionpreview.guest` 1.1.0. 비교 기준: Notion Android 0.6.4324 실기기 캡처(`%TEMP%/notion-rea-10324/device-findings.md`), Obsidian Android 1.15.1 APK 정적 분석. 사용자 문서(팀프로젝트3)는 열거나 수정하지 않았다. 테스트 문서는 `REA-` 접두사.

## 1. 버튼 구조와 효율

| 상단 탭 | 하위 버튼 | 사용 빈도 성격 |
|---|---|---|
| 홈 | 개요 · 오늘 · 빠른 입력 (3) | 매일 |
| 문서 | 문서 목록 · 문서 관계 · 즐겨찾기 · 파일 보관함 · 가져오기/내보내기 (5) | 매일 / 가끔 섞임. 1080px에서도 마지막 항목이 잘림 |
| 업무 | 할 일/일정 · 캘린더 · 프로젝트 · 공유 공간 (4) | 매일 / 공유 공간은 설정성 |
| AI | 제안 검토 · AI 연결 (2) | 제안 도착 시 / 최초 1회 설정 |

주요 작업 탭 수(실측):

| 작업 | 플래너 | Notion |
|---|---|---|
| 새 문서 | 1 (하단 연필) | 1~2 |
| 즐겨찾기 추가 | 3 (… → 문서 도구 → 즐겨찾기) | 2 (… → 즐겨찾기에 추가) |
| 휴지통 이동 | 3 + 확인 | 2 |
| 하위 문서 | 2 (☰ → 새 문서) 또는 3 | 2 (+ → 페이지) |
| 블록 AI 요청 | 길게 누르기 → 입력 → 동의 체크 → 아래로 스크롤 → 보내기 | 하단 도구 AI → 입력 |
| 프로젝트 | 2 (업무 → 프로젝트) | 해당 없음 |

판단: 상단 4칸 중 AI 칸이 가장 효율이 낮다. AI 연결은 한 번 설정하면 끝나고, 제안 검토는 제안이 있을 때만 필요하다(편집기 안에 이미 수용/거절 배너가 있음). 프로젝트를 AI 탭 안에 넣는 것은 의미가 맞지 않는다(프로젝트는 문서·할 일을 묶는 업무 단위).

권장안(구조 변경이므로 승인 후 적용):
1. 상단 4번째 칸을 **프로젝트**로 바꾼다. 업무는 할 일/일정 · 캘린더 2개로 줄어든다.
2. **AI 연결**은 작업 공간 메뉴 → 설정으로, **제안 검토**는 홈 개요의 배지 행(건수 있을 때만)과 편집기 배너로 옮긴다.
3. **공유 공간**은 Notion처럼 좌상단 작업 공간 메뉴로 옮긴다.
4. 문서 탭은 목록 · 즐겨찾기 · 파일 3개로 줄이고, 가져오기/내보내기와 문서 관계는 `모든 도구`로 보낸다.
5. 문서 작업 메뉴(…)는 Notion처럼 한 시트에 즐겨찾기 · 하위 문서 · 이동 · 휴지통을 바로 노출한다(현재 2단계).

결과: 상단 하위 버튼 14개 → 8개, 즐겨찾기·휴지통 3탭 → 2탭.

## 3. 문서 관계 시각화

실기기 관찰: 모든 문서를 2열 격자에 같은 크기로 깔고, 계층선이 같은 접점에서 합쳐져 어느 부모인지 구분이 어렵다. 카드마다 "문서 / 드래그로 이동"이 반복되고, 하단 안내 문구가 시스템 탐색 막대와 겹친다. 정보는 홈·문서 트리와 중복이고 좌표는 기기 전용이다.

비교: Notion에는 그래프가 없다. Obsidian은 그래프 뷰가 있지만 실사용 가치는 문서별 **백링크(연결된 문서) 패널**에서 나온다(`metadataCache.resolvedLinks/unresolvedLinks`).

판단: 현재 형태의 독립 탭은 쓸모가 낮다. 데이터(`stella_document_links`, Markdown 링크 해석)는 유지하고, 편집기 하단에 **연결된 문서/백링크 목록**으로 노출하는 편이 효율이 높다. 캔버스는 `모든 도구`에 남긴다.

## 6. 저장 구조 비교 (Obsidian 중심)

| | Obsidian 1.15.1 | Notion 0.6.4324 | 플래너 |
|---|---|---|---|
| 원본 | 볼트 폴더의 `.md` 파일 | SQLite `block`(parent_id, content, version, crdt_data) | SQLite `memos`(title, body Markdown) + `stella_document_meta.blocks_json` |
| 설정 | `.obsidian/app.json`, `appearance.json`, `hotkeys.json`, `workspace(-mobile).json`, `core-plugins` | 내부 DB | `settings`, `integration_preferences` |
| 색인 | IndexedDB `<appId>-cache`의 `file`·`metadata` 저장소. 워커가 링크·제목·태그·frontmatter를 파싱, 언제든 재생성 | `offline_page` 동기 커서 | 링크 테이블 `stella_document_links` + 본문 Markdown 링크 해석 |
| 링크 | `[[이름]]`, 이름 변경 시 자동 갱신, `resolvedLinks`/`unresolvedLinks` | 블록 ID | 문서 ID |
| 이력 | 파일 복구 플러그인: IndexedDB `<appId>-backup`(path·ts 인덱스) 자동 스냅샷 | `transactions`(isUndoTransaction) | `memo_versions`, `stella_document_versions`(수동 저장), `originals` |
| 삭제 | `.trash` 폴더 또는 시스템 휴지통 | `moved_to_trash_time` | 소프트 삭제(`deletedAt`) |
| DB 뷰 | Bases 코어 플러그인(frontmatter 속성 기반) | `collection_*` 테이블 | 표 블록만 |

참고할 점: ① 원본과 재생성 가능한 색인을 분리(플래너도 링크 테이블을 Markdown에서 다시 만들 수 있게 유지). ② 백링크 맵(해결·미해결)을 계산해 3장의 "연결된 문서" 패널에 쓴다. ③ 일정 간격 자동 스냅샷(Obsidian 파일 복구 방식)을 버전 기능에 추가. 동기화·충돌 계약은 바꾸지 않는다.

## 7. 이번 변경과 검증

- `DocumentEditor.js`: 새 문서 첫 저장 시 `setParams({memoId})`, 실행 취소 1초 묶음.

- `mobileModelPolicy.mjs`: Gemma `minAvailable` 1.5GiB → 1GiB.
- `plugins/with-cleartext.js` + `app.json`: http 서버 주소 허용.
- 검사: local+integration 209/209, mobileModel 1/1, web·Android export 성공. 게스트 APK(`C:\sapk`, `EXPO_PUBLIC_STELLA_GUEST_PREVIEW=1`) 재빌드·설치 후 뒤로 가기·실행 취소·화살표·기기 AI·내 서버 AI 실기기 확인. 동작 줄이기 변경은 APK 미포함(번들·테스트만).
