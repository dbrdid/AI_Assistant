## 1. 수정 우선순위

- 동의: 상대 날짜, 값 누락, GBNF 실제 로드 순서. GBNF는 값의 의미를 보장하지 않는다.
- 반대: 날짜를 모델 입력에 넣는 방식. 프롬프트와 frozen config가 바뀌고 B단계 비교 조건도 깨지므로, 앱이 기기 날짜로 계산해 모델 값과 대조하는 편이 작다.
- 근거(날짜): `appCommands.mjs:55-57`은 명시 날짜만 대조한다. "내일 장보기"와 날짜가 전혀 없는 "장보기 할 일"에 `2020-01-01`을 넣은 출력이 모두 승인 카드까지 갔다.
- 근거(값 누락): `appCommands.mjs:91`은 값 없는 명령을 검증 없이 반환하고, `:113` 문법도 값 없는 블록 추가를 허용한다. "예산 초안을 문단으로 추가해줘"에 `표 블록 추가`, `최상위로 이동`, `현재 버전 저장`, `즐겨찾기 해제`, `휴지통 열어줘`가 모두 승인 카드까지 갔다.
- 추가: 수정 범위는 c05/c07만이 아니라 값 없는 명령 전체의 작업 종류 대조여야 한다.

## 2. Q4_K_M·IQ4_XS·Q3_K_M

- 동의: 현재 48문항으로 우열이나 후보를 확정할 수 없고, S22의 llama.rn에서 grammar on/off를 분리해야 한다.
- 반대: 같은 48문항을 후보 선별에 재사용하는 것. 38문항은 임계값 0.84를 정한 보정셋이고(`REPORT.md:56`), c05/c07/c11/c31은 이번 수정의 근거가 된다.

## 3. S22 메모리와 모델 수명

- 동의: 로드 조건과 수명 방식은 S22의 실패율, PSS, 로드 시간을 측정한 뒤 정한다.
- 보완: mmap 설명만으로 조건을 낮출 수 없다. ARM repack 대상이 Q4의 2,199,142,400바이트(73.3%)로 계산되어 별도 버퍼 복사가 예상된다. 헤더 계산값이며 실측 RSS는 아니다.
- 추가: 요청마다 로드하고(`mobileModel.native.js:93,146`) 측정 시작이 로드 전이므로(`:68,122`), 재로드가 4초를 넘으면 짧은 명령의 첫 토큰 4초 기준은 구조적으로 불가능하다.
- 판정: S22에서 재로드 포함 첫 토큰 P95가 4초를 넘으면 컨텍스트 유지와 백그라운드·메모리 경고 시 해제를 후보로 올린다.

## 4. C단계 QLoRA

- 동의: 앱 계약 공백을 학습으로 덮지 않고, A·B 수정과 GBNF 실측 전에는 시작하지 않는다.
- 보완: 진입 조건은 "수정 후 앱 검증을 통과한 잘못 실행" 또는 "GBNF 적용 후에도 남는 모델 표현 오류"가 새 선별셋에서 사전 기준을 넘을 때로 한정한다.
- 근거: 현재 안전 거부(Q4 21/48)는 문법 미적용 조건이라 모델 능력 부족의 근거로 쓸 수 없다(`REPORT.md:60-61,100`).
- 가설: 수치 기준은 선별셋을 동결할 때 함께 정한다.
