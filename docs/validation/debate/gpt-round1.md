# GPT 1라운드 검토

기준은 2026-11-23 작업본 기록이다. 직접 측정과 문서상 제안은 구분한다. 코드는 수정하지 않았다.

## 1. 수정 우선순위

1. 상대 날짜 c11/c31을 먼저 막는다. 임의 날짜가 승인 경계까지 도달하는 것은 데이터 오기록 위험이며, 오늘 날짜 누락은 프롬프트 문구만으로 해결되지 않는다. 모델 입력에 로컬 기준 날짜와 시간대를 공급하고, 해석되지 않으면 승인 불가로 반환한다. 근거: docs/validation/orca-resume-result.md 7절, c11/c31 기록.
2. 그 다음 c05/c07 값 누락 실행을 차단한다. 요청에 값이 있는데 모델이 빈 슬롯을 반환하면 불완전한 변경으로 승인 카드를 만들지 말고 사용자에게 필수 필드를 확인한다. 근거: 같은 문서의 남은 결함 기록.
3. GBNF는 방어선으로 취급한다. 실제 런타임 로드와 유효 출력 확인은 S22 연결 후 첫 검증이지만, 스키마 준수는 날짜 의미와 값 보존을 입증하지 않는다. 두 실행 차단 수정과 회귀 재생을 먼저 하고 GBNF 검증을 병행한다.

## 2. Q4_K_M·IQ4_XS·Q3_K_M

48문항 개발 경로에서 통과는 각각 22/48, 29/48, 29/48이다. Q4 대비 정확 McNemar p는 0.039와 0.065로 보정 기준 0.025를 넘었다. 세 모델 모두 잘못 실행한 사례가 있어 우열이나 배포 후보를 확정할 근거가 부족하다. 근거: docs/validation/orca-resume-result.md 4절.
최소 실험은 대상 기기와 llama.rn 설정을 고정하고 동일 48문항을 grammar off/on 각각 실행해 문법 적용, 파싱, 의미 슬롯, 오실행을 분리 비교하는 것이다. 로드 성공, 첫 토큰, 메모리도 함께 기록한다. 이는 후보 선별이며 독립 품질평가나 기기 합격 판정이 아니다.
독립 300문항은 최종 후보 확정 후 기준 Q4와 후보 하나에만 실행한다. 이를 후보 선택에 쓰지 않는다.

## 3. S22 메모리와 모델 수명

현재 로드 조건은 GGUF 3.01GB에 여유 700MiB를 더한 사용 가능 메모리를 요구한다. mmap은 주소 공간 매핑이며 모든 페이지의 상주 RAM을 보장하지 않으므로, 이 조건은 S22에서 거부가 잦을 수 있다는 우려를 실측 없이 수치화했다. 근거: docs/validation/s22-performance-goal.md.
ARM repack은 파일 크기와 로드 특성이 달라질 수 있다. GGUF 파일 크기만으로 조건을 추정하지 말고 실제 실패율, PSS, 메모리 경고, 로드 시간을 측정한 뒤 조정한다.
요청마다 로드·해제할지 여부는 현재 근거로 결정할 수 없다. 반복 명령의 재로드가 8초 목표를 깨는지, 보유 상태가 백그라운드와 메모리 경고에서 안전히 해제되는지 S22 반복 측정 후 판단한다. 근거: 같은 목표 문서의 재로드·30회 반복 기준.

## 4. C단계 QLoRA 진입 기준

A·B 뒤 품질 우려만으로 QLoRA를 시작하지 않는다. S22 런타임에서 GBNF 적용을 확인하고, 상대 날짜·필수 슬롯 누락·주변 블록 무변경을 보정셋에서 검사한다. 오류가 승인 경계까지 통과하거나 동결 평가에서 사전 품질 기준을 못 넘을 때 C단계를 검토한다.
오늘 날짜 입력 누락이나 승인 검증 공백은 학습으로 덮지 말고 앱 계약에서 먼저 해결한다. QLoRA는 모델 표현력 문제라는 근거, 분리된 학습·검증 자료, 원복 가능한 산출 경로가 있을 때 검토한다.
학습 도구가 설치되어 있지 않고 다운로드도 별도 승인 단계다. 사전 기준 전에는 실행하지 않는다. 근거: docs/validation/s22-model-optimization-plan.md A·C 단계.

## 5. 독립 300문항과 JSON 기준

한 줄 명령 경로에 JSON 99%를 그대로 적용하지 않는다. 명령 파싱률과 승인 후 의도 일치율을 측정하고, 잘못된 대상·누락 값 실행 0건 및 주변 블록 변경 0건을 안전 게이트로 둔다. 실제 JSON 생성 경로에만 구문·스키마 통과율을 적용한다. 수치 목표는 시험 전에 동결한다.
문항과 Codex 기준 응답은 후보 실행 전에 동결하고 해시를 기록한다. 다섯 영역과 블록 생성·수정·이동·거절 사례를 포함하며 유사 템플릿과 날짜 치환 문항은 같은 분할에 묶는다. 기대값과 채점 기준은 모델 입력에서 제외한다.
독립셋은 프롬프트 조정, 보정, 모델 선택에 재사용하지 않는다. 최종 후보가 정해지지 않았으면 실행을 보류한다. 근거: docs/validation/orca-resume-result.md 3절 및 docs/validation/s22-model-optimization-plan.md 데이터 규칙.
