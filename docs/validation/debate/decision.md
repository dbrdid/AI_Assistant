# GPT·Claude 토론 결정

기록일: 2026-11-23. Run `run_005c12950703`, 코디네이터 `term_29de06a6-1e3d-4d0a-886f-0cf70aa1b76a`, GPT 검토 `term_0e6d6adf-80c2-4778-8a5d-be863698aec9`. 이 파일은 커밋하지 않는다.

상태: 토론 종료(2라운드). 사용자가 상대 날짜 되묻기를 결정했고 선별셋을 동결했다(6절 1·2번 완료). **소스 수정, 새 워커, 의존성·모델 설치, 커밋·푸시·APK 배포는 보류 중이다.** 검증기 구현과 E1~E5, S22 지표, 독립 300문항은 모두 NOT_RUN이다.

## 1. 합의

1. 수정 순서는 상대 날짜, 잘못된 작업 실행, GBNF 실제 로드 순이다. GBNF는 형식만 제한하고 값의 의미는 보장하지 않는다.
2. 날짜 검증은 앱에서 한다. 프롬프트와 문법은 바꾸지 않는다.
3. 기존 48문항은 회귀 확인에만 쓴다. 후보 선별은 새로 동결한 소규모 선별셋으로 한다.
4. grammar on/off 결과는 섞지 않는다. 후보 비교는 S22의 같은 llama.rn 설정에서 한다.
5. 로드 조건과 모델 유지 방식은 S22의 실패율, PSS, 로드 시간, 첫 토큰을 잰 뒤 정한다.
6. QLoRA는 앱 수정과 GBNF 실측 뒤에도 모델 표현 오류가 선별셋의 사전 기준을 넘을 때만 검토한다.
7. 300문항의 정답은 사람이 검토 가능한 기대 명령과 저장 후 기대 상태다. Codex 응답은 초안 보조로만 쓴다. 규칙 라우터와 모델 경로는 분리 집계한다.

## 3. 토론 전제 정정 (원본 대조)

1. **앱 수정도 frozen config에 영향을 준다.** `appCommands.mjs`의 파일 해시가 고정되어 있어 한 줄만 바꿔도 `tests/integration/s22-metrics.test.mjs:61`이 실패한다. 프롬프트와 문법을 그대로 두면 `commandPromptFileSha256`만 갱신하면 되고, 렌더링 프롬프트·문법 해시는 유지된다.
2. **대조만으로는 "내일" 요청이 실행되지 않는다.** 모델은 오늘 날짜를 모른다. c11·c31의 녹화 출력 6건 중 5건이 프롬프트 예시 날짜 `2026-11-27`이고 1건은 `2026-11-28`이다. 대조를 넣으면 이 요청은 대부분 되묻기가 된다. 따라서 대조 대신 상대 표현을 감지해 되묻는다 (5절 결정 1).
3. **값 없는 명령만 고치면 d06이 남는다.** Q4는 "겨울 독서 감상문 초고를 문단으로 추가해줘"를 `문서 만들기: 겨울 독서 감상문 초고`로 바꿨다. 값은 원문과 같지만 작업이 틀렸다. 작업 종류 대조는 **값 있는 명령까지** 포함해야 한다.
4. **잘못 실행 8건은 세 유형으로 모두 설명된다.** 상대 날짜 c11·c31(Q4 2, IQ4_XS 2, Q3 1), 값 누락 c05·c07(Q4 2), 값 있는 작업 불일치 d06(Q4 1). IQ4_XS와 Q3의 잘못 실행은 모두 날짜 유형이다.
5. **c11 라벨이 두 파일에서 다르다.** `s22-calibration.json`은 `execute`, B단계 `gold.json`은 되묻기(`null`)다. 전자는 값 근거 비율 보정용, 후자는 날짜 근거까지 본 채점용이다. 보정셋은 해시 고정이므로 고치지 않고, 회귀 채점은 `gold.json`을 따른다.
