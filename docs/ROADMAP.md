# 개발 순서와 검증 기준

## 1. 모바일 수동 기록

입력·메모·할 일·일정·기본 검색을 서비스/Repository/SQLite로 연결합니다. 앱 재시작 후 보존, 잘못된 날짜, 빈 입력, 중복 저장, 저장 실패, revision 충돌을 검증합니다.

## 2. AI 서버 최소 경로

모델과 서버 실행 환경을 선정하고 인증된 텍스트 정리 요청 하나를 구현합니다. 모델 런타임은 앱이 아니라 서버에 배치합니다. 서버 인증·인가, 입력 크기, 과부하, 타임아웃, 결과 스키마, 로그의 본문·비밀 값 미노출을 검증합니다.

인터넷에 모델 런타임을 직접 노출하기 전에 인증·접근 제한을 갖춘 API를 둡니다. 모델명·GPU·서버 비용은 측정 후 결정하며 이 커밋에서 특정 제품을 채택하지 않습니다.

## 3. 모바일 AI 연결과 승인

AI API Client → 앱 서비스 → 검토 → 사용자 승인 → SQLite 저장을 연결합니다. AI 미동의, 오프라인, 인증 만료, 잘못된 응답, 취소 후 늦은 응답, 편집 후 오래된 초안, 승인 중복을 검증합니다.

## 4. 기록 질문과 출처

조건 해석과 근거 답변을 고정 단계로 연결합니다. 삭제·권한 밖·AI 제외 기록이 전송되거나 표시되지 않는지, 근거 ID와 날짜가 맞는지 검증합니다.

## 5. 플랫폼 검증과 전체 확장

Android 실기기에서 네트워크 변경·앱 중단/재개·저장 보존·접근성을 확인한 뒤 iOS를 검증합니다. 이후 기존 전체 목표인 블록/보기·프로젝트·미디어/회의·기억·동기화/협업·도구 실행을 단계별로 연결합니다. 일정과 인력은 실제 범위에 맞춰 다시 산정합니다.

## 수용 상태

현재 문서 외 앱·서버 구현과 실기기·실제 모델 시험은 미실행입니다. 위 순서는 구현 계획이며 통과 기록이 아닙니다. 출시 전에는 한국어 정리/날짜/출처 정확도, 왕복 응답 지연, 서버 동시 처리·RAM/GPU·비용, 장애 복구·데이터 보호의 기준을 먼저 정하고 측정합니다. 모바일 추론에 쓰던 자원 합격선을 서버에 그대로 적용하지 않습니다.
