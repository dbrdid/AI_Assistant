# 모바일 앱 작업 지원 범위

기준은 커밋 `8c5c099`의 `frontend/Frontend_UI/App.js`, `src/navigation/AppNavigator.js`와 현재 변경이다. 홈의 **작업 공간 메뉴 → 앱 작업 요청** 또는 문서의 **문서 도구 → 이 문서에 작업 요청**에서 시작한다. 실행할 명령과 대상을 검토한 뒤 승인해야 저장한다. 정확한 형식은 기기 내에서 바로 해석한다. 자연스러운 문장은 **자연어 요청 해석**에서 명확하면 규칙으로 변환하고, 모호하면 되묻고, 그 외에는 로컬 모델로 보낸다. 어느 경로든 같은 검증과 승인을 거친다. 모델에 전달하는 값은 사용자가 입력한 요청과 명령 형식이며 문서 블록 본문은 전달하지 않는다.

실행 경계는 현재 계정·공간·접근권한과 문서 revision을 검사한다. 편집은 문서 저장소의 블록 정규화·본문 변환과 낙관적 동시성 검사를 사용한다. 승인 전 취소와 중복 승인은 추가 쓰기를 만들지 않는다. 로컬 모델 출력도 동일한 허용 명령에 맞아야 하며, 모델이 출력한 임의 코드·도구명은 실행 경로가 없다. 기기 전용 블록 메타데이터와 동기화되는 메모 본문의 범위는 기존 저장소 계약을 따른다.

합성 SQLite 회귀 검사는 저장소 루트에서 `node --test tests/integration/mobile-commands.test.mjs`로 실행한다. 브라우저 미리보기에서의 확인과 Android·iOS 기기 추론 결과는 별도로 집계한다.

## 실제 앱에서 관찰한 결과

2026-11-23, 합성 계정과 새 브라우저 프로필에서 Expo의 실제 앱 진입점으로 시작했다. 홈 메뉴에서 새 문서 생성, 제목 블록 추가, 2번→1번 이동, 본문 수정, 삭제 검토 후 취소를 확인했다. 새로고침한 홈에 저장한 제목과 본문이 남았다.

PC Ollama와 프로젝트의 Qwen3.5-4B 가중치를 연결해 같은 앱의 자연어 경로도 실행했다. Q4_K_M이 “두 번째 블록을 첫 번째 자리로 옮겨 줘”를 “2 번 블록을 1 번으로 이동”으로 변환했다. 번호와 단위 사이 공백을 허용한 뒤, 검토 화면에서 승인하면 “확정” 블록의 순서가 1번째에서 2번째로 바뀌었다. Q5_K_M은 “현장 기록” 제목 블록 생성 요청을 처음에는 그대로 반복했다. 명령 예시를 보완한 뒤에도 “문단 추가: 현장 기록”을 반환했다. 앱은 이 형식을 거부했고 원본 블록 수와 순서는 그대로였다. 한 사례씩의 결과이므로 양자화별 성공률 추정에는 사용할 수 없다. Android·iOS 기기에서 같은 화면의 터치와 가중치 추론은 이 검증에서 NOT_RUN이다.
