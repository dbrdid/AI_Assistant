# 백엔드 지침

루트 AGENTS.md를 함께 따릅니다.

- db/schema.sql은 버전 관리되는 SQLite 스키마(변경은 db/database.js의 번호 단계로 추가), rpc/는 모든 권한 검사와 쓰기, tests/는 실제 SQLite 검증에 사용합니다.
- 모든 테넌트 관계에 workspace_id를 포함한 외래키를 사용합니다. SQLite에는 RLS가 없으므로 DB에 쓰는 코드는 rpc/ 안에만 두고, 역할 허용 목록(rpc/index.js)과 DB 파일 권한을 확인합니다.
- 권한은 현재 멤버십을 기준으로 검증합니다. 워크스페이스 역할을 상한으로 하여 제한된 상위 폴더와 문서 ACL을 모두 만족해야 합니다.
- 문서 변경, Revision, Audit, Receipt, 변경 로그, Sync Head는 하나의 트랜잭션으로 처리합니다.
- workspace 잠금과 동일한 순서의 권한 변경 처리를 통해 커밋 순서와 Pull 커서를 보장합니다.
- op_id 재사용은 요청 해시를 검증합니다. 삭제는 tombstone으로 남기며 오프라인 수정으로 부활시키지 않습니다.
- 변경 알림에는 사용자별 신호(user_signals)만 내보냅니다. 제목·본문·암호문·키·제한 문서 ID는 싣지 않습니다.
- AI Gateway는 JWT·현재 권한·전송 범위 동의·예산을 검증합니다. 예산 예약과 큐 삽입은 원자적으로 수행합니다.
- 장시간 AI 처리는 worker에서 수행합니다. 불확실한 호출을 무조건 재시도하거나 예약금을 해제하지 않습니다.
- 서비스 역할 키는 모바일에 넣지 않습니다. KMS·키 복구·실제 제공자 연동을 모의 구현으로 대체했다고 숨기지 않습니다.
- 로컬 테스트와 운영 마이그레이션은 분리합니다. 운영 접속·데이터 변경·배포는 별도 승인 대상입니다.
