# 모바일 텍스트 AI 한국어 비교 평가

2026-11-23, 소스 기준 `8c5c099`. Qwen3.5-4B Q4_K_M과 Q5_K_M은 PC에서 검색 의도, 날짜, 인용, 할 일·일정 추출에서 서로 다른 오류를 냈다. 두 모델 모두 13개 중 고정 자동 기준을 처음에 7개, 프롬프트를 한 번 보완한 뒤 10개 충족했다. 보완 후에도 Q4는 오후 3시 일정을 종일로 만들어 앱에서 시각이 소실됐다. Q5는 같은 일정의 시각을 보존했다. 이 표본만으로 기본 배포 모델을 확정할 수 없다.

## 측정 범위와 재현

[한국어 사례](mobile-cases.json)의 `reference`는 이 평가를 작성한 Codex의 합성 기준 응답이다. 각 항목에 모델 입력, 기대 필드, 기대 앱 상태를 저장했다. 기준 응답은 사용자 UI용 의미 기준이며 검색 계획의 경우 실제 UI 문자열과 다를 수 있다. `reference`, `expect`, `state`는 모델에 보내지 않는다. 다섯 텍스트 라우트에서 메모 정리, 검색 계획, 자료 기반 답변, 요약·추출, 안건 판단을 평가했다. OCR, 음성, 실제 SQLite 검색 결과 선택, 터치 UI는 범위 밖이다.

Windows PC, i7-11800H, RTX 3060 Laptop GPU 6144 MiB, Node 26.13.0, Ollama 0.40.16. 로컬 호스트의 프로젝트 전용 모델 디렉터리에 bartowski 가중치를 내려받았다. 가중치 blob은 Q4 3,013,027,808바이트, Q5 3,443,763,168바이트였다. 결과 JSON의 digest는 Ollama 모델 매니페스트를 식별한다. 4096 컨텍스트, 최대 출력 768, 온도 0, seed 42, think false, 라우트별 JSON 스키마 제약, 순차 요청을 두 모델에 동일하게 사용했다. 검색·답변·안건에서는 앱의 프롬프트 렌더러를 직접 사용하고 메모 정리·분석에서는 Edge 엔트리의 지시문과 스키마를 읽었다. 날짜는 2026-11-23 월요일, 시간대는 서울로 고정했다.

로컬 Ollama를 127.0.0.1:11459에서 구동한 뒤 아래 명령을 사용한다. 재실행은 같은 모델·버전의 결과 파일을 덮어쓰므로 과거 측정을 보관하려면 별도 체크아웃에서 실행한다.

```powershell
$env:OLLAMA_HOST='127.0.0.1:11459'
$env:OLLAMA_MODELS=Join-Path (Get-Location) 'ai/eval/data/models'
# 별도 터미널에서 위 환경 변수로 ollama serve 실행
ollama pull hf.co/bartowski/Qwen_Qwen3.5-4B-GGUF:Q4_K_M
ollama pull hf.co/bartowski/Qwen_Qwen3.5-4B-GGUF:Q5_K_M
node ai/eval/run-mobile.mjs check
node ai/eval/run-mobile.mjs Q4_K_M
node ai/eval/run-mobile.mjs Q5_K_M
node ai/eval/run-mobile.mjs Q4_K_M repair
node ai/eval/run-mobile.mjs Q5_K_M repair
node ai/eval/replay-mobile.mjs
node --test tests/integration/ai-service.test.mjs
```

## PC 실측

각 행은 같은 13개 요청에 대한 1회 측정이다. 자동 통과는 JSON 스키마와 사례별 필드·내용 조건을 모두 만족한 건수다. 생성 속도는 모든 응답의 출력 토큰 합계를 Ollama의 디코딩 시간 합계로 나눴다. 앱 전체 지연, 첫 토큰 지연, 모바일 지속 속도는 별도 지표다.

| 모델·프롬프트 | 유효 JSON 스키마 | 자동 통과 | PC 생성 tok/s | 실패 사례 |
|---|---:|---:|---:|---|
| [Q4 기본](Q4_K_M-baseline.json) | 13/13 | 7/13 | 51.2 | 다음 주, 후속 질문, 상자 수, 관찰 요약, 할 일, 일정 |
| [Q4 보완](Q4_K_M-repair.json) | 13/13 | 10/13 | 46.9 | 관찰 요약, 할 일, 일정 |
| [Q5 기본](Q5_K_M-baseline.json) | 13/13 | 7/13 | 44.1 | 다음 주, 후속 질문, 상자 수, 관찰 요약, 할 일, 일정 |
| [Q5 보완](Q5_K_M-repair.json) | 13/13 | 10/13 | 42.7 | 상자 수, 할 일, 일정 |

[보완 지시문](repair-prompt.txt)은 Q4 기본 출력에서 확인한 사실 역할 혼동, 검색 전 부재 단정, 과거 사실의 할 일 변환, 원문 인용 변형에 대응했다. 두 모델에 같은 지시문으로 13개 전부를 다시 실행했다. 제출 장소와 방문 장소의 차이를 예로 들어 정리 사례와 표현이 일부 겹친다. 동일 개발셋 재검사이므로 개선치의 일반화는 미확인이다.

| 재현 사례 | 원문과 실제 영향 |
|---|---|
| 후속 파일 검색 | Q4 기본은 검색 전에 파일이 없다고 답했다. 보완 후 두 모델이 search를 반환했지만 원문에 없는 11월 16일부터의 기간과 open 상태를 넣었다. 자동 검사는 검색 의도·파일 종류·단풍 키워드·reply만 확인해서 이 오류를 놓쳤다. |
| 근거 인용 | 두 모델 모두 12+7=19를 맞혔다. 기본 응답은 원문의 ‘12개’를 ‘12 개’로 고쳐 원문 일치 검사에 실패했다. Q4 보완은 통과했고 Q5 보완은 실패했다. 날짜·시간을 포함한 할 일·일정에서도 동일한 공백 문제가 남았다. |
| 원문 보존 | 두 모델 기본 정리에서 제출 장소를 답사 장소로 바꿨다. 키워드 자동 검사는 통과했다. 보완 후 둘 다 제출 장소를 보존했지만 관찰 요약에서는 실제 비가 온 것을 강우 예보로 바꿨다. |
| 할 일·일정 상태 | 메모 분석 결과를 실제 Gateway 검증과 모바일 서비스에 다시 넣어 인메모리 SQLite에 재생했다. 네 결과 모두 미리보기에는 제안 0건, 제출 메모에는 11월 27일 할 일과 요약이 승인 대기로 생성됐다. 원문 보존, 최종 할 일 0건을 확인했다. 낭독회에서 Q4는 두 차례 모두 all_day=true와 start_time=15:00을 함께 생성했다. 검증과 저장을 거치면 시각이 빈 문자열이 된다. Q5는 두 차례 모두 15:00을 보존했다. |
| 안건 | 기본 응답은 미논의 판정에도 무관한 회의 구절을 붙였다. 보완 후 두 모델 모두 근거를 비우고 미논의로 답했다. 안건 상태 위주의 자동 통과율에는 이 차이가 반영되지 않는다. |

기존 모바일 서비스 테스트 8개도 통과했다. 취소, 원문 수정, 계정 전환, 동의 철회, 미리보기, 승인 대기 저장을 검사한다. 이 테스트의 provider는 고정 응답이다. 모델 출력을 사용한 메모 경로의 별도 재생은 [재생 스크립트](replay-mobile.mjs)로 반복할 수 있다.

## 300문항과 기기 검증

첨부 계획의 5개 영역별 60문항을 정식 평가 목표로 둔다. 이번 13개는 개발셋으로 격리하고, 300개를 구성할 때는 같은 문장의 날짜·수량 치환 사례가 개발셋과 시험셋에 걸치지 않게 분리한다.

| 영역 | 60문항의 구성 예시 |
|---|---|
| 한국어 대화·지시 | 인사, 기능 밖 요청, 검색 의도, 조건 없는 기록 요청, 불명확한 요청 |
| 요약·추출 | 원인과 예측, 취소와 미완료, 장소 역할, 담당자·기한 누락, 근거 없는 제안 |
| 논리·수학 | 수량 합산·차이, 주 경계, 자정·월말, 충돌 일정, 단위 보존 |
| JSON·구조 | null·빈 배열, 종일과 특정 시각의 상호 제약, 유효 날짜, 근거 없는 상태 변경 |
| 긴 문맥·다중 턴 | 지시어, 정정 공지, 인용 위치, 근거 부족, 4096토큰 경계의 앞·중간·끝 회수 |

각 영역에 독립 원문과 정답을 동결하고 BF16/Q4/Q5를 같은 조건으로 실행한다. 정답형에는 대응 문항별 정확도 차이를 %p로, 서술형에는 모델명을 숨긴 사실·누락·환각 심사를 적용한다. 300문항 실행, BF16 대비 3%p, JSON 99%, Galaxy S22 및 iPhone 15 Pro의 512토큰 입력 첫 토큰 지연 P95·15분 지속 생성 10 tok/s·앱 피크 메모리·발열·오프라인 작동은 모두 **NOT_RUN**이다.

## 연구 근거

- MobileAIBench는 기기에서 양자화별 과제 품질과 지연·자원 소비를 측정한다. 이 평가에서는 기능별 의미 오류를 따로 기록하고, 기기 성능을 제품 앱과 같은 조건에서 후속 측정하도록 했다. [MobileAIBench 논문](https://arxiv.org/abs/2406.10290)
- BFCL은 호출 구조·인자와 다중 턴을 평가한다. 앱의 검색 조건, 날짜, 상태, 근거를 별도로 검사하는 방법에 참고했다. 표의 수치는 본 앱의 합성 평가 결과다. [Berkeley Function Calling Leaderboard](https://gorilla.cs.berkeley.edu/leaderboard.html)
- PocketPal은 실행 중인 휴대폰에서 토큰 속도와 메모리를 확인하는 벤치마크를 제공한다. 같은 가중치의 기기 비교에 활용할 수 있고, 본 앱의 UI·DB 경로 지연은 본 앱에서 따로 측정해야 한다. [PocketPal 공식 저장소](https://github.com/a-ghorbani/pocketpal-ai#-benchmark-your-device)
- Qwen은 비사고 응답을 채팅 템플릿 옵션으로 제어하는 예를 제공한다. 여기서는 앱 자체 호스트와 동일하게 Ollama think=false를 전달했다. 기기 엔진의 템플릿 동등성은 미확인이다. GGUF는 커뮤니티 배포본이며 결과 파일에 실측 버전을 고정했다. [Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-4B) · [GGUF 배포 자료](https://huggingface.co/bartowski/Qwen_Qwen3.5-4B-GGUF)
