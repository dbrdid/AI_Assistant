# 문서 요약 설계

2026-11-11. 현재 범위: 텍스트 문서 요약 및 근거가 있는 핵심 내용 추출. 오케스트레이션·도구 실행·분산 추론은 포함하지 않는다.

## 데이터 흐름

호출자 → 입력 검증·스냅샷 → Ollama 구조화 생성 → 결과·근거 검증 → 요약 반환.

AI 담당은 프롬프트·모델 연동·요약 결과 검증과 실제 모델 평가를 맡는다. 로컬 백엔드는 읽기 권한 확인, 문서 조회, 외부 전송 동의, 결과 수신 시 revision 충돌 검사와 사용자 승인 후 저장을 맡는다. 클라우드 API의 인증·사용자별 요청 제한·큐·Azure VM 관리는 이 모듈 밖의 책임이다.

## 입출력 계약

입력은 documentId(영문·숫자·하이픈·밑줄, 최대 80자), revision(0 이상 안전한 정수), text(비어 있지 않은 최대 8000 UTF-16 코드 단위)만 허용한다. 초과 문서는 자르지 않고 INVALID_INPUT으로 거절한다. PDF/DOCX 원본 읽기·OCR·긴 문서 분할 요약은 후속 범위다. 호출자가 텍스트를 추출해야 한다.

출력은 documentId, inputRevision, result를 포함한다. result는 summary(최대 2000자), keyPoints(1~5개)이다. 각 핵심 내용은 text(최대 500자), sourceQuote(최대 1000자)를 포함하며 sourceQuote는 원문에 정확히 존재해야 한다. 알 수 없는 필드와 잘못된 형식은 거절한다. 저장 전에 호출자가 현재 revision과 inputRevision을 비교해야 한다.

일치하는 인용문 검사는 근거 위치 확인이며 요약의 의미적 진실성을 보장하지 않는다. 원문에 있는 숫자·날짜·부정·불확실성이 요약에서 보존되는지는 모델 평가와 사용자 검토가 필요하다.

## 실행과 실패 처리

provider.generate({text, schema, signal}) 인터페이스를 주입한다. 기본 Ollama 제공자는 JSON Schema를 format에 전달하는 구조화 생성이며 네이티브 함수 호출을 사용하지 않는다. think=false, temperature=0, num_ctx=8192, num_predict=2048로 시작한다. 문자 수 제한이 토큰 수 보장은 아니므로 입력 잘림·컨텍스트 적합성은 실제 한국어 모델로 시험한다.

런타임 주소와 모델은 신뢰된 호스트 설정에서 주입한다. API 요청이 임의의 주소를 지정하게 하지 않는다. 모델은 자동 다운로드하지 않는다. 문서는 데이터로 전달하며 문서 안 지시를 실행하지 않도록 프롬프트를 구성한다. DB·셸·도구 실행 경로는 없다.

전체 요청에 기본 30초, 최대 120초 기한과 호출자 취소를 적용한다. HTTP 응답은 최대 65536바이트이며 실패 응답, 미완성 생성, 길이 제한 종료, 잘못된 JSON을 거절한다. provider는 취소 신호를 준수해야 한다. 주입 제공자가 무시해도 호출자는 기한에 반환하지만 해당 제공자의 내부 작업 종료까지 보장하지는 않는다.

오류 코드: INVALID_INPUT, INVALID_CONFIGURATION, INVALID_MODEL_OUTPUT, MODEL_UNAVAILABLE, MODEL_TIMEOUT, CANCELLED. 외부 오류 메시지나 문서 원문을 로그에 기록하지 않는다. 자동 재시도·유료 API 대체 호출은 없다.

## 구현 경계

현재 코드는 ai/src/documents.js의 라이브러리이며 서비스 배포나 기존 Fastify API 연결은 수행하지 않았다. Ollama 연동은 문서 요약 전용이며 기존 cloud의 organize/conditions/answer 계약을 수정하지 않는다. 각 런타임별 인증·사용자 격리·동시성 정책은 호스트에서 적용한다. 기기 단독 또는 서버 단독 실행을 선택하고, Azure 사양·성능·비용은 별도 실측한다.
